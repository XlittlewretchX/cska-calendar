# ⚽ CSKA Calendar

Один подписной календарь всех **опубликованных в официальном источнике матчей основной мужской команды ПФК ЦСКА Москва**. РПЛ, Кубок России, товарищеские встречи, сборы, международные турниры и Суперкубки попадают в один файл; списка разрешённых турниров нет. Молодёжная команда, ЦСКА-2, женские команды и «Легенды» исключаются.

Проект работает на бесплатных GitHub Actions и GitHub Pages без сервера. Это независимый проект, не официальный продукт клуба.

## Подписка

Постоянный адрес:

```text
https://xlittlewretchx.github.io/cska-calendar/calendar.ics
```

[Открыть страницу календаря](https://xlittlewretchx.github.io/cska-calendar/) · [Подписаться через webcal](webcal://xlittlewretchx.github.io/cska-calendar/calendar.ics) · [Состояние данных](https://xlittlewretchx.github.io/cska-calendar/status.json)

Нужна **подписка по URL**. Скачивание файла и разовый импорт событий не обеспечивают обновлений. Статус фактической публикации приведён в конце этого документа.

### iPhone и iPad

Откройте «Календарь» → «Календари» → «Добавить календарь» → «Добавить подписной календарь». Вставьте HTTPS-адрес выше, нажмите «Найти» / «Подписаться» (название зависит от версии системы), подтвердите добавление. Авторизация не требуется. Можно также открыть ссылку `webcal` со страницы проекта.

### Mac

Откройте «Календарь» → «Файл» → «Новая подписка на календарь». Вставьте HTTPS-адрес, нажмите «Подписаться». Выберите имя и частоту автообновления, например каждый час. Для доступности на устройствах одного Аккаунта Apple выберите расположение iCloud, если оно доступно. [Инструкция Apple](https://support.apple.com/ru-ru/102301).

Apple самостоятельно решает, когда обновлять подписку. Проект публикует данные ежедневно, но момент их появления на устройстве не гарантирован. `REFRESH-INTERVAL` / `X-PUBLISHED-TTL` предлагает интервал в один час.

## Что уже получено

Первичная загрузка 12 октября 2026 года: **1 751 матч**, **38 сезонов**, период **29.03.1992 — 29.05.2027**, в том числе **282 товарищеские встречи**. Все эти матчи имеют дату или диапазон и включены в `.ics`. На момент загрузки было 12 предварительных диапазонов и один матч с датой без времени. Дальнейшие числа смотрите в `public/status.json`.

Например, реально опубликованная встреча «Ростов — ЦСКА», РПЛ, тур 18, имеет диапазон **26 февраля — 1 марта 2027 года**. Она занимает четыре дня:

```ics
DTSTART;VALUE=DATE:20270226
DTEND;VALUE=DATE:20270302
```

Конечная граница `DTEND` исключительная. Известный день без времени создаёт однодневное событие. Точный старт преобразуется из московского времени в UTC, длительность условно равна двум часам. Используется IANA `Europe/Moscow`, включая исторические изменения UTC+4/UTC+3; часовой пояс устройства не изменяет фактический момент начала.

## Источники и исследование сайта

Основной источник: [официальный календарь ЦСКА](https://pfc-cska.com/ru/matchi/kalendar-matchej/) и [официальный архив результатов](https://pfc-cska.com/ru/matchi/rezultatyi-matchej/).

Это Nuxt-приложение. Полный каталог сезонов обнаруживается в JSON-блоке `__NUXT_DATA__`, а встречи загружаются из публичного API, которым пользуется сам сайт:

```text
https://api.pfc-cska.com/site/listing/matches?lang=ru&parent=82&season_id=223981
https://api.pfc-cska.com/site/listing/matches?lang=ru&parent=82&season_id=223981&is_finished=true
```

`223981` — пример идентификатора сезона, а не константа загрузчика. Сезоны и текущий сезон определяются заново при каждом запуске. Параметр `parent=82` и ID основной команды `11630` подтверждены реальными ответами сайта. `match_team_a` — хозяева, `match_team_b` — гости.

**Важный нюанс API:** `is_finished` должен быть строкой `true`. Числовое `1` игнорируется и возвращает предстоящие встречи. Выдача предстоящих матчей в исследованных запросах возвращала текущее расписание даже при указании старого сезона; архив с `is_finished=true` учитывает сезон. Загрузчик проверяет сезон и признак завершённости в архиве.

На первом запуске / `--bootstrap` загружаются все обнаруженные архивы. Затем текущее расписание и архивы текущего/предыдущего календарного года обновляются ежедневно. Новые сезоны загружаются сразу. Старые архивы перепроверяются минимум раз в 30 дней, чтобы найти дополнения и исправления без ежедневной нагрузки на сайт. Товарищеские матчи и зимние турниры найдены в этом же API, поэтому сторонний источник пока не потребовался.

Используется режим `limit=0` самого сайта, который сейчас возвращает сезон целиком. Если API начнёт разбивать такую выдачу, загрузчик следует `total_pages`, проверяет `current_page`, общий размер и отсутствие повторных ID. Таймаут — 30 секунд, до трёх попыток при временных сбоях, пауза не меньше 500 мс между запросами, поддержка числового `Retry-After`.

Реальные снимки HTML/JSON для воспроизводимых тестов и их исходные URL находятся в `tests/fixtures/`.

## История, переносы и защита данных

`data/matches.json` хранит нормализованную историю, исходные ID и ссылки, результаты, диапазоны, метаданные событий и состояние загрузки сезонов. Исчезнувшие из сайта встречи не удаляются. Отсутствующее поле не стирает ранее известный стадион или результат; исходный `0:0` у незавершённой встречи не считается итогом.

UID строится из источника и ID матча и не зависит от времени, турнира, стадиона или счёта. Уточнение диапазона до даты, добавление времени, перенос, исправление турнира и результата меняют существующее событие. `SEQUENCE` увеличивается и `DTSTAMP` / `LAST-MODIFIED` обновляются только при изменении содержимого события. Одинаковые сведения дают идентичный файл календаря.

Механизм объединения поддерживает несколько источников и приоритет официальных данных. Сопоставление разных источников требует совпадения хозяев/гостей, турнира, сезона и тура/стадии; без тура — пересечения дат. Разные ID одного источника не объединяются. Неоднозначное сопоставление завершает обновление ошибкой, вместо случайного объединения двух встреч. При добавлении адаптера без исходных ID ему нужны устойчивые локальные идентификаторы; не создавайте их из меняющейся даты.

Явная отмена сохраняет встречу с `STATUS:CANCELLED`; перенесённая встреча остаётся с `STATUS:TENTATIVE` до уточнения. Исчезновение строки само по себе не доказывает отмену. Даты, стадионы и результаты никогда не додумываются.

Схемы Zod проверяют сохранённые и входящие данные. Пустая общая выдача, неполная страница, повреждённый JSON, несоответствие архивного сезона или потеря более 25% строк уже известного объёмного архива останавливают обновление. Пустой новый архив допустим. Сильное падение числа предстоящих матчей также требует проверки. Все источники сначала полностью читаются и проверяются; запись начинается только после успешной генерации календаря. Файлы готовятся во временных путях и заменяются через `rename`; при обычной ошибке записи выполненные замены откатываются. GitHub Pages получает артефакт только после успешной загрузки и сохранения данных в Git.

## Запуск локально

Требуется Node.js 22 LTS (последняя версия ветки 22) и npm.

```sh
git clone https://github.com/XlittlewretchX/cska-calendar.git
cd cska-calendar
npm ci
npm run update
```

Для принудительного повторного чтения всех архивов:

```sh
npm run bootstrap
```

Переменные окружения и секреты для чтения источника не нужны. Запускать команды следует из корня репозитория. Уже сохранённая история автоматически используется при обновлении. Сборка: `npm run build`, затем `node dist/index.js` из корня.

## Проверки

```sh
npm run check
npm test
npm run typecheck
npm run lint
npm run format:check
npm run build
```

`check` последовательно запускает все проверки. Тесты используют зафиксированные реальные ответы и независимый парсер `ical.js`; сетевые запросы для тестов не нужны. Проверяются точное время, неизвестное время, диапазоны через месяц/год/високосный день, стабильный UID, результаты, переносы, стадионы, отмены, сохранение исчезнувшей истории, ошибки источника, пагинация, разные источники, несколько встреч с одним соперником, временные зоны, Unicode/экранирование и исключение молодёжных команд.

## GitHub Actions и Pages

`.github/workflows/update.yml` запускается ежедневно по `0 3 * * *` UTC — примерно **06:00 Москвы**, вручную через `workflow_dispatch` и при изменениях кода в `main`. GitHub может задерживать задания по расписанию. Параллельные обновления/публикации сериализуются через `concurrency`.

Workflow выполняет `npm ci`, проверки, загрузку и объединение истории, генерацию `.ics`, коммит изменённых данных и публикацию каталога `public/` через официальный `actions/deploy-pages`. Токен бота имеет `contents:write` только в задании обновления; публикация отдельно получает `pages:write` и `id-token:write`. Коммит бота не создаёт цикл запусков. Ошибка источника оставляет ранее опубликованный календарь доступным. CI проверяет изменения отдельно; Dependabot ежемесячно предлагает обновления npm и Actions.

Настройка нового размещения: репозиторий → **Settings → Pages → Build and deployment → Source → GitHub Actions**. Для бесплатного Pages репозиторий должен быть публичным. URL файла остаётся тем же после каждой публикации. [Документация GitHub](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).

Ручное обновление: **Actions → Update calendar and deploy Pages → Run workflow → main → Run workflow**. Опция `bootstrap` перечитывает все архивы. Если ветка защищена от прямого коммита бота, потребуется разрешить этому workflow запись в `main` или адаптировать сохранение через PR. Настройки защиты проект автоматически не ослабляет.

При ошибке откройте красный запуск в Actions и шаг `Fetch matches and merge history`. Проверьте доступность источника и сохранённые образцы. Не удаляйте `data/matches.json`, чтобы «починить» парсер: это уничтожит историю и метаданные UID.

## Ограничения покрытия

- **Абсолютная полнота всех матчей клуба не гарантируется.** Доступный официальный архив начинается в 1992 году; в отдельных сезонах он неполон. Не опубликованные, удалённые до первой загрузки или не внесённые в API матчи невозможно восстановить достоверно. Новые будущие стадии Кубка и товарищеские появляются только после публикации клубом.
- Встречи без даты и без диапазона сохраняются в JSON, но не создают фиктивное событие. Их число отражается в `status.json`.
- В исследованном API нет подтверждённого отдельного поля отмены. Адаптер поддерживает явные `match_is_cancelled`, `match_is_postponed` и текстовый `match_status`, если источник их начнёт предоставлять; обнаружение всех отмен сейчас гарантировать нельзя. Новая опубликованная дата и время уже обрабатываются автоматически.
- Архив иногда относит январские товарищеские встречи к следующему футбольному сезону. Сезоны, результаты и признаки определённости времени сохраняются согласно источнику. Старые записи с `00:00` могут быть историческими заполнителями, если сайт не пометил время неизвестным; проект не может независимо подтвердить историческое время каждого матча.
- Сайт или API могут изменить контракт; такой ответ приводит к понятной ошибке и сохраняет предыдущие файлы. Защита от неполной выдачи консервативна: массовое исправление архива потребует проверки человеком.
- Старые архивы обновляются раз в 30 дней, недавние — ежедневно. При аварийном завершении процесса или отключении питания между заменами нескольких локальных файлов локальные артефакты могут потребовать повторной генерации; workflow не публикует неуспешный запуск.
- Подписка проверена независимым парсером iCalendar и публичной HTTP-загрузкой после публикации; визуальное обновление на физическом iPhone/iPad/Mac требует подписки на устройстве владельца.
